## Что должно заработать

`POST /api/import/inspect` принимает источник — usdb-песню по id, загруженные файлы (zip или .txt + аудио + обложка) или ссылку (на zip или на GitHub-репозиторий/папку) — раскладывает в `imports/<token>/` и отвечает списком найденных песен (контракт в `interfaces.md`). `POST /api/jobs/import` по токену и индексу песни переносит её файлы в `jobs/<id>/in/` и ставит задание `import` с params по контракту. Дубли — как у generate.

## Критерии приёмки

- [ ] inspect `source=usdb`: `UsdbClient.fetch_song` → `song.txt` + ссылки YouTube (из `#VIDEO` и комментариев, без повторов) + обложка `co=`/usdb (скачивается, если есть); `source=files`: один zip или набор файлов; `source=url`: zip по ссылке (≤ `MAX_IMPORT_MB`, проверка сигнатуры zip), GitHub `github.com/<o>/<r>[/tree/<ветка>/<папка>]` → codeload-архив (ветка по умолчанию через `api.github.com/repos/<o>/<r>`), только песни из папки
- [ ] Ошибки по-русски: нет песен — 400 «В архиве нет песен UltraStar (.txt с #TITLE и нотами)»; размер — 413; ссылка не скачалась/не zip — 400 с `field=url`; `PackError` → 400
- [ ] В ответе на песню: `existing_song_id` (`find_by_name`), `warnings`; `meta.json` в `imports/<token>/` хранит разбор; токен старше часа → 410 «Загрузка устарела, загрузите заново»; старые `imports/*` удаляются при inspect и в периодической уборке web
- [ ] jobs/import: поля по спецификации; 409 с `song_id` при дубле без `replace`; 409 «Эта песня уже в очереди» по типам generate и import; свой `audio` — проверка mp3 и лимит `MAX_UPLOAD_MB`; ни звука в файлах, ни своего, ни ссылки YouTube → 400 «Нужен звук: загрузите mp3 или вставьте ссылку на YouTube» (field=audio)
- [ ] params ровно по контракту `interfaces.md`; исходные байты .txt не меняются
- [ ] `MAX_IMPORT_MB` в `.env.example` с русским комментарием строкой выше, в `/api/defaults` как `max_import_mb`
- [ ] Тесты через `FakeHttp`: usdb, files (пак из 2 песен), url zip, GitHub, устаревший токен, дубль, нет звука; полный pytest зелёный
