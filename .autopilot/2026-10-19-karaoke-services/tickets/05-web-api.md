## Что должно заработать

Сервис FastAPI реализует весь REST API из «Границ»:
- создание заданий с валидацией (mp3 по сигнатуре и лимиту, обязательные поля, дубли в очереди, `replace` при существующей песне);
- отмена, перезапуск и повторная выкладка;
- лог: кусками и через SSE;
- список песен из индекса с фоновым пересканированием и баннером недоступности;
- `exists`;
- карточка песни, текст (свой или извлечённый);
- ноты структурой: GET и PUT, с сохранением версии в корзину; дуэты и `#RELATIVE` только для чтения;
- аудио с Range, обложка;
- удаление в корзину, корзина и восстановление;
- настройки папки результата с проверкой; пароль не возвращается, пустое поле = «не менять»;
- `/api/defaults`, `/api/status`.

Middleware HTTP Basic по `WEB_PASSWORD`. Фоновая очистка корзины при старте и каждые 6 ч. Статика из `web/static/` отдаётся с `/`, сами страницы делает таск 06; пока достаточно заглушки `index.html`. OpenAPI — на `/api/docs`.

## Критерии приёмки

- [ ] Шов 2: тесты `TestClient` на каждый эндпоинт: успешный путь и ошибки с русским `detail`
- [ ] При заданном `WEB_PASSWORD` без пароля 401 получают все пути (включая SSE и статику); при пустом всё открыто
- [ ] `POST /api/jobs/generate`: не-mp3 → 400 «Это не mp3-файл»; дубль в очереди → 409 «Эта песня уже в очереди»; существующая песня без `replace` → 409 с `song_id`
- [ ] `GET/PUT /api/songs/{id}/notes`: круговое преобразование без правок не меняет файл; правка слога меняет только его строку; прежний .txt появляется в корзине; дуэт → `editable:false` и PUT 409
- [ ] `GET /api/songs/{id}/audio` отвечает 206 на Range-запрос
- [ ] `GET /api/settings/output` никогда не содержит пароля; `PUT` без пароля сохраняет прежний; `POST …/test` возвращает понятную ошибку
- [ ] `docker --context desktop-linux compose up -d web` поднимает сервис, `/api/status` отвечает с хоста по `localhost` и по IP ПК
