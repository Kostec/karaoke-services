## Что должно заработать

Ничего нового — исправляются отложенные замечания ревью интерфейса. Одно из них теряет данные пользователя (перегенерация удаляет сохранённый LRC), одно вводит в заблуждение (импорт пака, прерванный устаревшей загрузкой, не говорит, что часть песен уже в очереди), остальные — повторы текстов сервера на фронте, всплывшие в трёх тасках.

## Критерии приёмки

- [ ] Перегенерация: если LRC в форме не трогали, сохранённый `source/lyrics.lrc` не удаляется (поле `lyrics_lrc` не шлётся); удаляется только при явной очистке/замене текста. Выбор «передать / сбросить / не трогать» — именованная чистая функция рядом с `lrcAfterEdit`, с тестом; правило сброса LRC при новой вставке и при загрузке файла — тоже в чистой функции с тестом
- [ ] Импорт пака: если на N-й песне пришёл 410, сообщение называет, сколько песен уже поставлено в очередь
- [ ] Тексты ошибок, которые даёт сервер, фронт показывает из `detail` (без своей копии): 503 поиска текста; `NEED_AUDIO`/`WARN_SYNC` в импорте — фронт не фильтрует серверные предупреждения сравнением строк (показывает их как есть, свои добавляет только для того, чего сервер не знает — например, выбранный пользователем свой mp3); текст дубля — из одной константы
- [ ] Поле ссылки YouTube на карточке заполняется по тому же правилу, что `pickAudioSource` (первая непустая после trim)
- [ ] Имена: токен разбора — `token`, не `pack.id`; переменные модуля импорта говорят, что внутри (не `t/u/c`) — с учётом ловушки `test_repo_config` (не `token: …`/`token = …` литералом в одной строке; например, `packToken`)
- [ ] Стили диалога поиска текста — в CSS, не inline; при отказе от замены текста список вариантов остаётся открытым
- [ ] В `lyrics-search.js` комментарием сказано, какой разборщик LRC для показа текста (`stripLrc`), а какой — для паритета с форком (`parseLrc`)
- [ ] `node --test tests/frontend/` зелёный, число тестов не меньше прежнего (53); полный pytest зелёный
