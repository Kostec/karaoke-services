## Что должно заработать

Ничего нового для пользователя — те же функции становятся надёжнее, а повторы кода получают одного владельца. Источник — замечания ревью, отложенные на приёмку; одно и то же замечание («вторая копия») всплыло в четырёх тасках, поэтому чинится сейчас.

## Критерии приёмки

Повторы — одно место у каждого правила:
- [ ] ссылка `https://www.youtube.com/watch?v=<id>` строится одной функцией (сейчас `usdb._WATCH` и `songpack._WATCH`)
- [ ] `existing_song_id` для песни — одна функция рядом с `AppContext.find_by_name` (сейчас копии в `api_usdb` и `api_import`)
- [ ] поиск файла без учёта регистра — из `songpack`, без второй копии в `api_import._has_instrumental`
- [ ] умолчание `MAX_IMPORT_MB` — в одном месте, `/api/defaults` берёт его оттуда
- [ ] состав params задания `instrumental` — одна функция в core, её зовут и `api_jobs`, и воркер (`_enqueue_instrumental`)
- [ ] общие помощники generate, которыми пользуется импорт (`_Staging`, `_queue_duplicate`, `_is_mp3`, `_cover_ext`, `_copy_limited`), — под публичными именами (без `_`), в `api_jobs` или общем модуле
- [ ] `INPUT_LRC` — в `paths.py` рядом с остальными `INPUT_*`
- [ ] тексты ошибок usdb в API — из самих исключений (`str(e)`), без второй копии; правило «пустой пароль — прежний» для usdb — в одном месте, мёртвая ветка убрана

Надёжность usdb (разметка не сверена с живым сайтом, поэтому разбор не должен быть хрупким):
- [ ] вход подтверждается положительным признаком (например, ссылка выхода/профиля в ответе), а не только отсутствием `LOGIN_INVALID`; тест на «чужую страницу» → ошибка входа
- [ ] `has_more` считается по строкам таблицы, а не по успешно разобранным
- [ ] HTML-сущности раскрываются в разобранной ячейке, не во всей странице до разбора (название с `&lt;…&gt;` сохраняется)
- [ ] разбор строки не зависит от порядка атрибутов

Сеть (нашла слепая приёмка: в работающем web 2 из 5 запросов к LRCLIB дали 503, ссылка GitHub 4 раза подряд «Нет связи с сервером codeload.github.com», хотя из того же контейнера другим процессом архив качался; после `compose restart web` — 49 песен):
- [ ] найти причину (например, долгоживущий `Http`/сессия, IPv6 без маршрута при таймауте 10 с, DNS при старте) и устранить её; в лог web пишется настоящая причина сетевой ошибки (тип исключения, адрес), без паролей и тел запросов
- [ ] одна повторная попытка на ошибке соединения/таймауте для идемпотентных GET и скачиваний; тест через FakeHttp или локальный сервер

Прочее:
- [ ] у `HttpError` есть признак превышения размера; `api_import` определяет 413 по нему; тест идёт через настоящий путь `FakeHttp.download` с телом больше `max_bytes`
- [ ] россыпь файлов с одинаковыми именами → 400 с понятным текстом (не молча затирать); ошибка размера для россыпи говорит про файлы, а не «Архив…»
- [ ] нечитаемый `in/lyrics.lrc` в воркере → в логе настоящая причина, а не «текст отличается»
- [ ] `GET /api/songs` читает params своих песен одним запросом, без N+1
- [ ] полный pytest зелёный, число тестов не меньше прежнего (403)
