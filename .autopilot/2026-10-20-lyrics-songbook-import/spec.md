# Спецификация: текст из сервиса текстов и импорт песен из сборников UltraStar

## Задача

Чтобы сгенерировать песню хорошо, нужен текст — сейчас его приходится искать в интернете
и вставлять руками. А многие песни уже давно кто-то сделал для UltraStar (usdb, паки
песен, архивы с русскими песнями) — и их не нужно генерировать заново, а приложение
умеет только генерировать.

## Решение

1. В форме новой песни (и при перегенерации) рядом с полем текста появляется кнопка
   «Найти текст»: по исполнителю и названию приложение ищет текст в LRCLIB, показывает
   найденные варианты, выбранный вставляется в поле.
2. Новый раздел «Импорт»: готовую UltraStar-песню можно взять
   - из usdb.animux.de — поиск по исполнителю/названию/языку (по умолчанию русский)
     прямо в приложении, со входом под аккаунтом пользователя (логин и пароль — в «Настройках»);
   - из zip-архива или набора файлов с компьютера/телефона (любой сборник: пак песен,
     ultrastar-es.org, GitHub-репозитории с русскими песнями);
   - по ссылке на zip.
   Если в архиве несколько песен — показывается список, можно выбрать нужные.
   Звук: из архива, из загруженного своего mp3 или с YouTube (ссылка из песни или своя).
   Галочка «Сделать минусовку» (по умолчанию включена) — после выкладки ставится
   обычное задание минусовки. Импортированная песня выкладывается в папку результата
   так же, как сгенерированная, и видна в «Песнях».

## Решения по реализации

1. **Сервис текстов — LRCLIB** (`https://lrclib.net/api/search?track_name=&artist_name=`, при пустом ответе — `?q=<исполнитель название>`). Бесплатный, без ключа, проверен 2026-10-20 (русские песни есть). Запрос делает web (у контейнера есть интернет), с `User-Agent: karaoke-services`, таймаут 10 с, до 10 результатов. Поставщик — за интерфейсом `LyricsProvider`, чтобы потом добавить другой.
2. **HTTP — стандартная библиотека** (`urllib.request` + `http.cookiejar`) в общем модуле `core/karaoke_core/http.py`: новой зависимости в образе web нет. Ограничение размера ответа, таймаут, ошибки → `HttpError` с русским текстом. Это же — шов для тестов: `create_app(http=…)` принимает фейк.
3. **usdb** (`https://usdb.animux.de/`) — клиент `UsdbClient` в web:
   - вход: POST на корень с `user`, `pass`, `login=Login`; неудача — в ответе есть `Login or Password invalid, please try again.` → `UsdbAuthError`; сессия (cookie) держится в памяти процесса; если в ответе любого запроса `You are not logged in. Login to use this function.` — один повторный вход и повтор запроса, второй раз — `UsdbAuthError`; `Datensatz nicht gefunden` → «Песня в usdb не найдена» (404). Строки взяты из usdb_syncer (`constants.py`, проверено 2026-10-20);
   - поиск: POST `index.php?link=list` с `interpret`, `title`, `language`, `order=rating`, `ud=desc`, `limit=50`, `start`, `details=1`; разбор HTML-таблицы; `has_more` = на странице ровно 50 строк;
   - ноты: POST `index.php?link=gettxt&id=N`, `wd=1`, текст из `<textarea>`;
   - детали: GET `index.php?link=detail&id=N` — ссылки YouTube из комментариев и обложка.
   Учётка хранится в `settings['usdb']` как JSON (как пароль шары — в БД), API отдаёт `{user, has_password}`. Переменных окружения для учётки нет — только «Настройки».
4. **Импорт в два шага.**
   - `POST /api/import/inspect` (multipart: `source=usdb|files|url`, `usdb_id` | `url` | `files[]`) — web скачивает/принимает, распаковывает в `DataPaths.import_dir(token)` (`imports/<token>/`), находит песни, отвечает списком. Ничего не ставит в очередь.
   - `POST /api/jobs/import` (multipart: `token`, `index`, `artist`, `title`, `audio?` (mp3), `youtube_url?`, `instrumental` (bool), `replace`, `song_id?`) — переносит файлы песни в `jobs/<id>/in/` (`song.txt` — исходные байты, `audio.<ext>` или `input.mp3`, `cover.<ext>`) и ставит задание `import`. Проверки дубля — как у generate (`find_by_name`, 409 с `song_id`; дубль в очереди — по типам `generate` и `import`).
   - Почему два шага: исполнитель и название известны только после разбора; пользователь видит, что нашлось, правит, выбирает песни из пака и решает про звук до того, как что-то стоит в очереди.
5. **Разбор сборника** — `core/karaoke_core/songpack.py`: безопасная распаковка zip (без выхода за папку, без ссылок, лимит суммарного распакованного размера = 2×`MAX_IMPORT_MB`, только `.txt .mp3 .ogg .m4a .opus .wav .flac .jpg .jpeg .png .webp`), поиск песен (txt с `#TITLE` и нотами, кроме `*.lyrics.txt`), для каждой — аудио по `#AUDIO`/`#MP3` (без учёта регистра), обложка по `#COVER` или ` [CO].`, ссылки YouTube из `#VIDEO` (`a=`, `v=`, `co=` для обложки, либо целиком URL/ID), язык, дуэт. Кодировка txt — `ultrastar.decode`.
6. **Задание `import`** (`ImportHandler`, `needs_gpu=False`): этапы — «Загрузка звука» (yt-dlp, если звук не из файла), «Подготовка» (ffmpeg → mp3 с одним аудиопотоком, как `audio_only_copy`; обложка: из файлов → `co=` → миниатюра YouTube), сборка папки (`#AUDIO`/`#MP3` → имя mp3, `#VIDEO`/`#BACKGROUND` убираются — файла видео нет), `postprocess.finalize(...)` с исполнителем/названием из формы и обложкой явно, `publish_song` (замена с откатом — существующая), mp3 кладётся в `in/input.mp3` до `_save_sources`, чтобы работала перегенерация. Если `instrumental=true` — после успешной выкладки ставится обычное задание `instrumental` для этой песни (`parent_id` = импорт). `PublishHandler` («Выложить повторно») понимает тип `import`.
7. **yt-dlp** уже есть в образе worker (зависимость UltraSinger). Вызов — `YTDLP_CMD` (по умолчанию `python -m yt_dlp`), `-x --audio-format mp3 --no-playlist`, через `run_command` (отмена и убийство зависших — как у остальных). YouTube требует JS-рантайм для части форматов — в образ worker ставится `deno`; `selfcheck` проверяет, что `yt_dlp` импортируется и `deno --version` работает.
8. **Фронт**: новый раздел `#import` «Импорт» (вкладки «usdb», «Файлы», «Ссылка») — `web/static/js/import.js`, чистая логика (выбор звука, предупреждения, разбор ответа) — `import-logic.js`; поиск текста — диалог в `new-song.js`, чистая логика (срез LRC-меток, отбор вариантов) — `lyrics-search.js`. Метка «Импорт» в очереди (`TYPE_LABEL`), метки «импорт»/«из usdb» на карточке песни (из `params.json` → `source`).
9. **Уборка**: `imports/<token>` старше часа удаляет web при очередном inspect и в периодической уборке; worker при старте — тоже.
10. **Новые переменные окружения** (в `.env.example` с русским комментарием): `MAX_IMPORT_MB` (лимит zip/ссылки, по умолчанию 500), `YTDLP_CMD` (подмена в тестах).

11. **Тайминги строк из LRC** (G06, G07). LRCLIB отдаёт `syncedLyrics` — это поле `synced` у `LyricsHit`. Форма шлёт в generate поле `lyrics_lrc` (текст LRC) и параметр `lrc_timing` (bool); web кладёт `in/lyrics.lrc`, `params.inputs.lrc`. Воркер при `lrc_timing` и совпадении строк передаёт UltraSinger `--lyrics_timing <in/lyrics.lrc>`. В форке UltraSinger (ветка `karaoke-local`, редактировать разрешил пользователь) флаг `--lyrics_timing` задаёт окна строк для выравнивания: вместо окон из `build_lyrics_segments` по распознанному whisper — окно строки = [метка строки − 0,5 с; метка следующей строки + 0,5 с], последней — до конца аудио; если строки текста и LRC не совпали (число или текст после нормализации) — метки не используются целиком, работает старая логика. `selfcheck` проверяет наличие флага. Изменения форка — коммитом в `karaoke-local` и `./scripts/export-ultrasinger-patch.ps1`; push в `fork` — только с согласия пользователя (образ worker собирается из `ULTRASINGER_GIT`).

12. **Папка с музыкой** (G08). Всё в браузере, кроме одного: inspect `source=files` начинает принимать относительные пути файлов (`webkitRelativePath`, имя части multipart) и раскладывает их в `imports/<token>/files/<путь>` с теми же проверками пути, что у GitHub-папки (`..`, абсолютные, диск → 400). Разделение на группы — чистая функция на фронте по расширениям и ссылкам `#AUDIO/#MP3` из .txt (сервер всё равно разбирает .txt сам в inspect). Генерация — существующий `POST /api/jobs/generate` (`generateForm`) по одному треку; текст — `/api/lyrics/search` по треку, первый вариант из `usableHits`. Без нового задания и нового эндпоинта.
