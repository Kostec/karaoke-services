# Спецификация: несколько хранилищ, «Песни» с фильтрами и копированием, правка границ строк

## Задача

Песни сейчас живут ровно в одном месте — там, что выбрано в «Настройках → Куда выкладывать». Переключил с шары Pi на локальную папку — настройки шары пропали, и чтобы вернуться, их надо вбивать заново. Если шара Pi выключена, генерация падает на выкладке, хотя песня уже готова. Посмотреть песни другого хранилища нельзя, перенести песню из одного места в другое нельзя, скачать готовую песню целиком — тоже. Яндекс Диска, Google Диска, второй шары или другой папки ПК среди вариантов нет.

Во вкладке «Песни» при сотне песен не найти нужное: нет фильтров (есть ли минусовка, исполнитель и т.д.).

В «Редакторе нот» строки бывают разбиты почти правильно, но крайняя нота строки должна относиться к соседней — сейчас можно только склеить две строки целиком. Панель «Текст» узкая: длинные строки обрезаются.

## Решение

- В «Настройках» — список хранилищ. Всегда есть «Локальное хранилище» (папка `/output` контейнера); к нему добавляются сколько угодно других: шара SMB, любая папка ПК, Яндекс Диск, любой WebDAV, Google Диск. У каждого — имя, «Проверить», «Изменить», «Удалить». Одно отмечено как **основная цель** — туда идут новые песни. Переключение основной цели ничего не стирает.
- Каждая новая песня выкладывается **всегда в локальное хранилище и в основную цель**. Основная цель недоступна — песня всё равно готова (лежит локально), а в основную цель её докладывает отдельное задание «Копирование», которое ждёт появления цели и повторяет раз в минуту.
- Вкладка «Песни»: переключатель хранилища сверху; фильтры (поиск, исполнитель, минусовка, видео, дуэт, обложка, происхождение) и сортировка; у песни — «Скачать .zip» и «Копировать в…»; для отфильтрованного списка — «Копировать показанные в…» (синхронизация: по умолчанию только недостающие).
- «Редактор нот»: серую пунктирную линию между строками можно тянуть мышью — ноты, через которые она прошла, переходят в соседнюю строку. Панель «Текст» растягивается за левый край, строки переносятся, а не обрезаются.

## Решения по реализации

1. **Хранилища — список в `settings`.** Ключ `targets`: `[{id, name, kind, ...поля типа, secret}]`, ключ `default_target`: `id` основной цели. `id` — короткий стабильный `t_<8 hex>`, присваивается при создании и **не меняется** при правке (раньше смена адреса меняла всё). Встроенное локальное хранилище — `id = "local"`, `kind = "local"`, корень `/output`, в списке всегда первое, не удаляется и не правится. *Почему:* стабильный id — то, на что ссылаются индекс, задания и корзина; адрес становится свойством, а не ключом.
2. **Миграция.** При первом чтении без `targets`: старое `settings[output]` (или `OUTPUT_*` env) превращается в хранилище; если оно SMB — `t_…` и основная цель; если локальное с подпапкой — хранилище «Папка ПК» внутри `/output`; если локальный корень — основная цель `local`. Строки `library` и записи корзины со старым `target_id` (`smb://…`, `local:/output…`) переписываются на новый `id` в той же транзакции. `jobs.params.target_id` старого формата сопоставляется по тому же правилу при чтении (без переписывания истории). `OUTPUT_*` в `.env` остаются как источник начального SMB-хранилища.
3. **Типы хранилищ** (`kind`): `local` (путь внутри `/output` или `/host`), `smb` (как сейчас), `webdav` (url, user, пароль, path; Яндекс Диск — тот же `webdav` с `preset: "yandex"` и url `https://webdav.yandex.ru`), `gdrive` (client_id, client secret, OAuth-токен, path). *Почему так:* WebDAV — официальный сетевой доступ Яндекс Диска без регистрации приложения; Google Диск сетевого доступа без OAuth не имеет.
4. **Реализации `Storage`:** `LocalStorage`, `SmbStorage` — как есть; новые `WebDavStorage` (PROPFIND/GET/PUT/MOVE/DELETE/MKCOL через `karaoke_core.http.Http`, запись — во временный файл тома и PUT целиком при закрытии; `_replace` — MOVE с `Overwrite: T`) и `GDriveStorage` (Drive REST v3 через `Http`: путь → id папок с кэшем на время жизни объекта; запись — resumable upload; `_replace` — переименование/перемещение файла; токен обновляется по refresh-токену, новый access-токен в БД не пишется). Сканирование библиотеки у сетевых — одним проходом по дереву с кэшем листинга, чтобы не делать запрос на каждую папку дважды.
5. **OAuth Google.** `GET /api/targets/gdrive/auth?draft=<token>` → редирект на `accounts.google.com` с `redirect_uri = <origin веба>/api/targets/gdrive/callback` (loopback для Desktop-клиента), scope `https://www.googleapis.com/auth/drive` (`drive.file` не видит уже существующие папки и песни на Диске), `access_type=offline`, `prompt=consent` (нужен refresh-токен). Черновик хранилища (client_id, client secret, path) лежит в памяти веба 10 минут под случайным `draft`; callback меняет code на токены через `Http`, проверяет доступ к папке и сохраняет хранилище. Окно Google открывается в новой вкладке; «Настройки» опрашивают `GET /api/targets/gdrive/draft/{draft}` до `connected|error`. Работает, когда браузер на том же ПК, что и веб (Google принимает loopback-redirect только для `localhost/127.0.0.1`); с телефона — подсказка «Подключите Google Диск с компьютера».
6. **Любая папка ПК.** В `docker-compose.yml` web и worker монтируют `${HOST_FOLDERS_ROOT:-./output}:/host`; новая переменная в `.env.example` с русским комментарием («корень, внутри которого можно выбрать любую папку, например `D:/`»); по умолчанию `D:/` (диск, где стоит проект). Сознательная граница: «любая папка» — любая внутри открытого контейнеру корня и `/output`; папка на другом диске становится доступной сменой `HOST_FOLDERS_ROOT` и `up -d` — так устроен Docker, контейнер не видит не примонтированное. `GET /api/targets/browse?root=host|output&path=` → подпапки (только каталоги, без `..`). Путь цели не может выйти за корень.
7. **Контекст хранилищ.** `AppContext` и `JobContext` получают `storage(target_id=None)` (None → основная цель) с кэшем по `(id, конфиг)`, `targets()`, `default_target()`, `local_storage()`. Все места, где песня уже известна, берут хранилище по `item.target_id`; `ctx.target()` остаётся только для «основной цели».
8. **Выкладка «локально + цель».** `publish_song` (generate/import/republish): сначала `local`; затем, если основная цель ≠ `local`, — основная цель. Сбой локальной — задание падает (как сейчас). Сбой основной цели — предупреждение в логе и постановка `copy`-задания `{song_id (local), target_id, replace: params.replace, wait: true}`; задание `done`. Замена/корзина/перенос видео — в каждом хранилище отдельно по прежним правилам. `source/` и `Songs` — как сейчас (одна запись на песню, `rel_dir`).
9. **Задание `copy`** (`needs_gpu=False`): params `{rel_dir, txt_name, from_target, to_target, replace, wait}`, ref `{artist, title, song_id}`. Шаги: `download_dir` из источника в `jobs/<id>/in/` (restart не качает заново) → если в цели папка есть: `replace=false` → лог «Уже есть в «X» — пропущено», `done`; `replace=true` → прежняя в корзину цели → `upload_dir` → индекс цели. `wait=true` и недоступна цель → задание возвращается в `queued` с `params.retry_at = now+60 с` и этапом «Ждёт хранилище «X»»; `claim_next` пропускает задания с будущим `retry_at`. Срока у ожидания нет: задание ждёт, пока цель не появится или пока его не отменят; карточка песни в локальном хранилище показывает «ждёт копирования в «X»» (по активному `copy`-заданию с `wait`). `POST /api/jobs/copy {song_ids: [...], target_id, replace, only_missing}` → `{queued: [...ids], skipped: N}`; дубль (та же песня → та же цель в очереди) → существующее задание.
10. **«Песни».** `GET /api/songs?target=<id>` (нет — основная цель) отдаёт как сейчас + `targets: [{id, name, kind, ok?}]`, `target: {id, name, ...}` и у каждой песни `updated_at` (mtime), `source` (`generated|usdb|files|url|null`). Фильтры и сортировка — **на клиенте**, чистым модулем `songs-filter.js` (`filterSongs(items, f)`, `artistCounts(items)`, `parseFilter(params)/filterParams(f)`) под node-тесты. *Почему на клиенте:* индекс уже приходит целиком, сотни-тысячи песен фильтруются мгновенно, состояние живёт в адресе.
11. **Zip.** `GET /api/songs/{id}/zip` — потоковая отдача `zipfile` (ZIP_STORED для медиа, DEFLATED для `.txt`) через генератор: файлы читаются из хранилища по одному; проверка доступности и список файлов — до первого байта (иначе 503). Без временного файла на диске.
12. **Корзина.** `TrashItem.target_id` = id хранилища; `restore` берёт хранилище по нему. Метка `target_label` пишется как сейчас.
13. **Статус веба.** `/api/status::output` — состояние основной цели и локального (`{default: {...}, local: {...}}`, прежние поля `ok/label/error` — основной цели, чтобы старый фронт не сломался).
14. **Редактор нот: перетаскивание разрыва.** Тайминг строки в UltraStar — это её крайние ноты (начало = начало первой ноты, конец = конец последней) плюс бит разрыва `- N` в паузе между строками. Поэтому «строка начинается/длится не так» правится двумя способами одной и той же линией: (а) отпускание **поверх нот** соседней строки переносит эти ноты в тянущую строку — меняются её начало или конец; (б) отпускание **в паузе** между последней нотой предыдущей строки и первой нотой следующей ноты не переносит, а ставит бит разрыва в точку отпускания (округление до бита). Правило границы: новая первая нота следующей строки — первая нота партии с `start >= beat`; бит разрыва = `beat`, если он попадает в паузу перед этой нотой, иначе конец предыдущей ноты. Модель: `moveBreak(state, id, beat, voice?)` — `id` — первая нота строки, перед которой стоит разрыв; граница не уходит дальше соседних разрывов (в каждой строке остаётся ≥1 нота); неизменяемо, ошибки — `throw Error` по-русски. Экран: `.ne-brk` получает зону захвата 8 px и `col-resize`, перетаскивание через `ctx.apply`/историю одним шагом, призрак линии во время тяги.
15. **Панель «Текст».** Ручка на левом краю `.ne-panel` (`pointer` события), ширина в CSS-переменной, `localStorage` `notesEditor.textPanelWidth`; строки панели — `white-space: normal; overflow-wrap: anywhere`, номер/статус — отдельной колонкой grid.

## Границы и швы

| Модуль | Владеет | Выставляет | Прячет |
|---|---|---|---|
| `karaoke_core.db` (Settings) | список хранилищ, основная цель, миграция | `Target` (dataclass: `id, name, kind, path, host, share, user, url, preset, client_id, secret, token`, `.public()`, `.label`), `Settings.get_targets() -> list[Target]`, `get_target(id) -> Target|None`, `save_target(Target) -> Target` (секрет None — прежний), `delete_target(id)`, `get_default_target_id()/set_default_target_id(id)`, `LOCAL_TARGET_ID = "local"` | формат JSON в `settings`, миграцию `output → targets`, переписывание `library/trash` |
| `karaoke_core.storage` | доступ к файлам хранилища | `make_storage(target: Target, *, http=None) -> Storage`; классы `LocalStorage`, `SmbStorage`, `WebDavStorage`, `GDriveStorage` с прежним интерфейсом `Storage` | протоколы, кэши путей, обновление токена |
| `web/app/api_targets.py` | REST хранилищ | `GET/POST /api/targets`, `PUT/DELETE /api/targets/{id}`, `POST /api/targets/test`, `PUT /api/targets/default {id}`, `GET /api/targets/browse`, `GET /api/targets/gdrive/auth`, `/gdrive/callback`, `/gdrive/draft/{draft}` | проверку перед сохранением, правило «пустой секрет — прежний», OAuth-черновики |
| контексты (`AppContext`, `JobContext`) | кэш открытых хранилищ | `storage(target_id=None)`, `targets()`, `default_target()` | закрытие/пересоздание при смене конфигурации |
| worker `handlers` | выкладку, копирование | `publish_song` (локально + цель), `HANDLERS["copy"]` | ожидание цели, порядок замены |
| `songs-filter.js` | фильтры/сортировка «Песен» | `filterSongs`, `artistCounts`, `parseFilter`, `filterParams`, `SORTS` | — |
| `notes-model.js` | модель | `moveBreak(state, id, beat, voice?)` | — |

`/api/settings/output` (GET/PUT/test) остаётся для совместимости: GET — основная цель в прежнем формате, PUT — правит её (или создаёт SMB/локальную и делает основной). Новый фронт им не пользуется.

**Швы для тестов** (существующие): `create_app(..., storage_factory=, http=FakeHttp())` + `TestClient` для API; `run_forever(...)` для воркера; `node --test` для чистых модулей. `WebDavStorage`/`GDriveStorage` проверяются через `FakeHttp` (маршруты PROPFIND/PUT/… и Drive REST) — реальные Яндекс/Google не трогаются. Экран редактора и «Настроек» — вручную в браузере.
