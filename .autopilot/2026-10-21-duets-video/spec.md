# Спецификация: дуэты и видео

## Задача

Дуэт из usdb или архива сейчас можно только посмотреть в «Редакторе нот»: поправить ноту, текст или разделить партии нельзя. Обычную песню, которую на самом деле поют вдвоём, в дуэт не превратить. Видео к песне не прикрепить вообще: импорт даже выбрасывает `#VIDEO`, а при генерации по ссылке на YouTube/VK видео теряется, хотя оно там есть.

## Решение

- В «Редакторе нот» дуэт правится как обычная песня: две партии разного цвета, у каждой своя дорожка слогов. Строку можно отдать певцу 1, певцу 2 или обоим. Имена певцов правятся. Обычную песню можно сделать дуэтом, а дуэт — обратно соло.
- У любой песни в «Песнях» есть «Видео…». Там видео добавляется или заменяется ссылкой или файлом, задаётся смещение. Там же видео можно убрать.
- В «Новой песне» (и по ссылке, и из своего mp3), в каждом треке «Импорт → Ссылка» и в каждой песне импорта (usdb, zip/файлы, ссылка на архив) есть блок «Видео». В нём: «без видео», «из ссылки песни» (когда звук берётся по ссылке на видео), «своя ссылка» или «файл». Для ссылок выбирается качество: по умолчанию 720p, при отсутствии — ближайшее.

## Решения по реализации

**Дуэт в файле.** Только `P1`/`P2` — так пишет usdb и читают USDX/Vocaluxe/UltraStar Play. «Оба» — дублирование строки в оба блока: стандартная практика, `P3` поддерживают не все. Порядок в файле: `P1`, все строки певца 1, `P2`, все строки певца 2, `E`. Разрыв перед первой строкой партии не пишется. Существующие `PlayerMark` переиспользуются, чтобы файл сохранялся байт в байт.

**Голос — у строки.** В API у строки `player: 1|2` (как уже отдаёт GET). В модели редактора голос хранится на ноте (`voice: 1|2|'both'`, одинаковый у всех нот строки), потому что операции модели работают с плоским списком нот. Порядок и соседи считаются по подпоследовательности нот одной партии. У ноты «оба» два источника: `src` (копия P1) и `src2` (копия P2).

**Имена певцов.** Читаются `#P1/#P2`, иначе `#DUETSINGERP1/2`. Пишутся `#P1/#P2`; `#DUETSINGERP*` обновляются, только если уже были.

**Видео — отдельное задание `video`.** Близнец `instrumental`: читает песню из `Storage`, пишет файл рядом с `.txt`, меняет заголовки через `set_header_line`. Без GPU. Веб не пишет на шару сам — как и раньше, запись в результат идёт только из воркера.

**Скачивание видео.** `yt-dlp -4 --no-playlist -f "bv*" -S "res:<H>,vcodec:h264,ext:mp4" --remux-video mp4`, для «лучшее» — без `res`. Сортировка `res:H` даёт ровно «720, иначе ближайшее снизу, иначе сверху». Только видеодорожка: звук у песни свой, файл меньше.

**Файл видео** кладётся как есть: перекодирование на ПК без NVENC в образе медленное, а файл пользователь выбрал сам.

**Имя файла** — `naming.video_suffix(ext)` → `<A - T>.<ext>` (по аналогии с `cover_suffix`); `.mp4` от yt-dlp.

**Индекс.** Миграция БД V2: `library.video TEXT`; `SongEntry.video` = `present("VIDEO")`. Ссылка вида `v=…` в `#VIDEO` файла не даёт, значит `None` — так и надо.

**Корзина и видео.** Удаление песни переносит папку целиком, видео тоже — иначе восстановление было бы неполным. При замене видео старый файл в корзину не идёт: он может весить сотни МБ, а версия `.txt` сохраняется.

**`_save_sources`** не копирует `in/video.*` в `source/`: видео уже лежит в папке результата, а дубль в томе data бессмыслен. В `params.json` пишется `video_url` (если был) — по нему перезапуск или перегенерация могут скачать видео заново.

**Перенос видео при замене.** В `publish_song`: если у заменяемой песни было видео, а в `result/` его нет, файл скачивается из старой папки в `result/` до того, как старая уйдёт в корзину, и заголовки переписываются под новое имя.

**Импорт.** `songpack` разделяет ссылки `a=` (звук) и `v=` (видео). У `FoundSong` появляются `video_links`, `video_file` (видеофайл из пакета по `#VIDEO`) и `videogap` (`v-gap=` или `#VIDEOGAP`). Видеорасширения входят в `ALLOWED_EXTS` (общий лимит `MAX_IMPORT_MB` остаётся). Блок «Видео» и в generate, и в import передаётся одинаково: `video_mode: none|source|url|file|pack`, `video_url`, `video_file` (File), `video_height`, `videogap`. Здесь `source` — ссылка звука (generate) или ссылка usdb/`#VIDEO` (import), `pack` — видеофайл из архива. Веб приводит это к `params.video = {mode, url?, height, gap?}` и `inputs.video` для файла. ImportHandler чистит `#VIDEO/#BACKGROUND/#VIDEOGAP`, как и раньше, а потом, если видео есть, ставит свои.

**Ссылки для видео у импорта:** сначала `v=` из `#VIDEO`, иначе выбранная для звука YouTube-ссылка — usdb в комментариях даёт как раз видеоклип.

**Лимит:** env `MAX_VIDEO_MB` (по умолчанию 2000) в `.env.example` с комментарием; `/api/defaults` отдаёт `max_video_mb`, `video_heights` [360, 480, 720, 1080, 0] (0 = лучшее), `default_video_height` 720.

**Прогресс:** `DownloadTracker` получает подпись этапа параметром: «Загрузка видео» — отдельный этап со своей шкалой.

## Границы и швы

| Модуль | Владеет | Выставляет | Прячет |
|---|---|---|---|
| `core/ultrastar` | формат `.txt` | `Song.tracks()` → `{1: [lines], 2: [lines]}` (соло → только `1`); `singer_names(song) -> (p1, p2)`; `set_singer_names(song, p1, p2)` | поиск `#P1`/`#DUETSINGERP1` |
| `web/notes` | GET/PUT нот | GET: `lines[].player` (1/2 у дуэта, нет у соло), `singers: {p1, p2}`, `duet: bool`; PUT: `lines[].player: 1|2|null`, `singers: {p1, p2}?` | раскладку блоков P1/P2, переиспользование меток, проверку по партиям |
| `editors/notes-model.js` | состояние редактора | нота `{…, voice: 1|2|'both', src2}`; State `{…, duet: bool, singers: {p1, p2}}`; `setVoice(state, ids, voice)`, `makeDuet(state)`, `makeSolo(state)`, `setSingers(state, p1, p2)`, `voiceNotes(state, v)`; все прежние операции — в пределах партии; `fromPayload` склеивает одинаковые строки P1/P2 в «оба», `toPayload` раскладывает обратно | порядок по партиям |
| `naming` | имена файлов | `video_suffix(ext)`, `VIDEO_EXTS` | — |
| `postprocess.finalize` | сборку папки результата | новые kwargs `video_path=None, videogap=None` → копия `<A - T>.<ext>` + `#VIDEO`/`#VIDEOGAP` | — |
| `worker handlers` | задания | `HANDLERS["video"]`; `download_video(ctx, job_id, url, dest_dir, height) -> Path`; ветка `video` в `PublishHandler` | yt-dlp-аргументы, перенос видео в `publish_song` |
| `web api_jobs` | приём заданий | `POST /api/jobs/video` multipart `{song_id, video(File)? , video_url?, video_height?, videogap?, remove?}` → карточка задания; generate и import принимают `video_mode, video_url, video_file, video_height, videogap` | `Staging` |

| фронт `api.js` | HTTP | `api.video(songId, form)`, `generateForm({..., video_mode, video_url, video_file, video_height, videogap})`, `importForm` с теми же полями; общий модуль фронта `video-block.js` (разметка блока «Видео» + чистая `videoFields(state)`) для формы, импорта и диалога | — |

Задание `video`: `params = {rel_dir, txt_name, target_id, video_url?, video_height?, videogap?, remove?, inputs.video?}`.

**Швы для тестов** — существующие: `tests/core` (ultrastar, songpack, postprocess, db, naming), `tests/api` через `TestClient` (notes GET/PUT, jobs/video, generate, import), `tests/worker` через `run_forever` с фейками (`fake_ytdlp.py` получает режим видео: без `-x`, с `-f`, пишет `.mp4`; `FAKE_YTDLP_MODE=novideo` — ошибка «Requested format is not available»), `tests/frontend` (notes-model, notes-panel-logic, api, import-logic, link-logic). Экран редактора и диалог видео проверяются вручную в браузере.

## Вне рамок

| Требование | Почему не сейчас |
|---|---|
| R01 — автоматическое деление голосов при генерации | UltraSinger делает один голос; по ответу на вопрос 1 — вне задачи |
| R10i — перекодирование своего файла видео под Pi | файл кладётся как есть; качество по ссылке выбирается |
| R03 — просмотр видео в вебе | в задаче не просили, синхронизацию проверяют в плеере на Pi |
| `#BACKGROUND` | не просили; импорт по-прежнему его вычищает |
