## Что должно заработать

Чистая модель редактора понимает дуэт. У ноты есть `voice: 1|2|'both'`, одинаковый у всех нот строки, и `src2` — источник копии P2 у строк «оба». State получает `duet` и `singers`. Все существующие операции работают внутри партии ноты. Новые операции: `setVoice`, `makeDuet`, `makeSolo`, `setSingers`, `voiceNotes`. `fromPayload` склеивает одинаковые строки P1/P2 в «оба», `toPayload` раскладывает их в блоки P1 и P2, как ждёт сервер. Для соло поведение и payload прежние — существующие тесты не меняются, кроме нового поля `duet`.

## Критерии приёмки

- [ ] `fromPayload` дуэта: ноты обеих партий в одном списке, у каждой `voice`; строка P1 и строка P2 с одинаковыми нотами (тип, начало, длина, высота, текст) → одна строка `voice:'both'` с `src` (P1) и `src2` (P2)
- [ ] `toPayload`: у дуэта строки с `player`, сначала все строки певца 1 (включая «оба»), потом все строки певца 2 (включая копии «оба» с `id: src2`), `break_beat` считается внутри партии; `singers` в payload; у соло payload как раньше
- [ ] порядок, соседи, перекрытия (`overlaps`, `validate`), `settle`, `splitNote`/`joinNext`, `startLine`/`mergeLineAt`, `addNote`/`addNotesToLine`, `deleteNotes`, `shiftTextBy` (слово/строка/песня), `retime` — по подпоследовательности партии; P2 с бита 0 не конфликтует с P1; «оба» конфликтует с обеими партиями
- [ ] `setVoice(state, ids, voice)` переводит целые строки выбранных нот; `makeDuet` (всё → певец 1, `duet:true`), `makeSolo` (всё → 1, копии «оба» схлопываются, `duet:false`), `setSingers`; ошибки — `throw Error` по-русски
- [ ] `validate` у дуэта называет партию: «Певец 2, строка 3: ноты перекрываются»
- [ ] логика панели: `lineAt`/`tapQueue` (или новые функции) работают по партии; `noteAt` для дуэта ищет в каждой партии (список не обязан быть отсортирован по времени глобально)
- [ ] `isDirty` и `history` учитывают голос и имена; `node --test tests/frontend/` зелёный, новые тесты на всё перечисленное
