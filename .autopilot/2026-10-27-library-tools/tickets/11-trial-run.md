# 11 — «Прогон» песни в браузере

**Требования:** R37, A02
**Зависит от:** 03, 07
**Зона:** `web/static/js/play.js` · `web/static/js/play-logic.js` · `web/static/js/song-page.js` · `tests/frontend/play-logic.test.mjs`
**Волна:** 4
**Ревью:** нет
**Модель:** сильная

## Что должно заработать

Раздел `#play?id=`: звук песни, сверху ноты по высоте с линией «сейчас», ниже крупно текущая строка с подсветкой спетых слогов и следующая; пауза, −5/+5 с, полоса; «Мелодия нот» — ноты звучат синтезатором `tone.js`; дуэт — две дорожки и имена; без звука, `#BPM` или с `#RELATIVE` — понятное объяснение. Кнопка «▶ Прогон» на странице песни и пункт в «…».

## Из брифа, дословно

> «Пробный прогон песни в браузере: бегущий текст с нотами и проверка высоты голоса через микрофон. Это крупная задача, но удобно проверять песню без запуска UltraStar.»
> «Думаю можно обойтись без микрофона.»

## Разделы спецификации

Истории 63–65; interfaces.md «фронт» (`play.js`, `play-logic.js`, `tone.js`).

## Критерии приёмки

- [ ] `timeline(payload)` переводит ноты в мс по `bpm/gap` (как `beatToMs` редактора), строки по партиям; `frameAt(timeline, ms)` → текущая/следующая строка, слог и доля (node-тест, включая дуэт и паузу между строками)
- [ ] Вид по макету, работает на 375 px; дорожка нот движется, слоги подсвечиваются по звуку
- [ ] «Мелодия нот» играет ноты вместе со звуком и замолкает на паузе и при уходе с раздела; ресурсы (`<audio>`, AudioContext) освобождаются в `hide()`
- [ ] Нет звука / нет `#BPM` / `#RELATIVE` — текст причины вместо прогона
