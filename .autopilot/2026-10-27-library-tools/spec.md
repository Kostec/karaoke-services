# Спецификация: инструменты библиотеки, баги страницы песни и тегов, фон и обложка, проверка, зеркало, очередь, уведомления, прогон

## Задача

У меня домашний сервис караоке: песен уже много, и копятся мелкие раздражения. Страница песни глушит музыку, стоит только поставить тег. Действия по одной песне надоели. Не видно, какие песни сломаны: нет звука, нет обложки, битая кодировка, дубли, копии на Pi расходятся с ПК. Фон песни не поставить, обложку приходится искать руками. Хранилище на Pi я поддерживаю копией вручную. Очередь генерации нельзя отложить на ночь или переставить. О готовности я узнаю, только если сижу у экрана. Проверить песню можно, только запустив UltraStar. Настройки не сохранить в файл.

## Решение

- **Страница песни** больше не перерисовывается целиком. После «Теги…», копирования и готового задания меняются только затронутые блоки, музыка и раскрытый текст остаются как были. Если хранилище песни отвалилось, это видно сразу, и действия с файлами гаснут.
- **Теги** отвечают внятно: пустой цвет — ошибка, а одновременное создание двух одинаковых тегов — «Такой тег уже есть», без падения.
- **Фон и обложка ставятся отдельным заданием без GPU**, как видео: свой файл, ссылка на картинку или выбор из найденных в iTunes, Deezer и MusicBrainz. Фон можно убрать.
- **В «Песнях» можно отметить несколько песен** и разом поставить или снять теги, скопировать, скачать одним zip, удалить в корзину или сделать минусовку. По каждой песне, которую пропустили, видна причина.
- **«Проверка библиотеки»** находит песни без звука, без обложки, с битой ссылкой `#VIDEO`, с битой кодировкой, дубли с разным написанием и копии, разошедшиеся между хранилищами. У каждой находки есть кнопка, которая её исправляет.
- **Зеркало хранилища**: одно хранилище само поддерживается копией другого, например «Локальное» → Pi. Зеркало добавляет новые песни и обновляет изменённые, а само ничего не удаляет. Песни, которые есть только в цели, показаны списком с кнопкой «Убрать в корзину».
- **«Редактор нот»** подсвечивает подозрительные места и умеет проиграть ноту её высотой.
- **Очередь**: задание можно отложить до заданного времени, например «на ночь», и поднять или опустить в порядке.
- **Уведомления о готовности и сбое** приходят в Telegram с любого устройства. Пока вкладка открыта, они показываются ещё и в браузере, если браузер это разрешает.
- **«Прогон»** проигрывает песню в браузере: бегущий текст с подсветкой слогов, ноты по высоте и, если включить, мелодия нот. Микрофона нет.
- **Резервная копия настроек**: теги со связями, хранилища, основная цель, логин usdb, настройки уведомлений и зеркал выгружаются одним файлом без паролей и токенов. Файл можно загрузить обратно, сначала посмотрев, что изменится.
- **Пакетная генерация по альбому или плейлисту** уже есть в «Импорт → Ссылка». Теперь ссылка на альбом, вставленная в «Новую песню», ведёт туда одной кнопкой, без копирования.

## Решения по реализации

- **Начатая правка двух багов тегов** (незакоммиченные `db.py`, `api_tags.py`) откатана на брифинге по ответу «Ок, но я бы откатил»; R04/R05 чинятся заново, с тестами.
- **R08 проверен по коду** (`RenameHandler._rename_tags` → `Tags.copy_key`, `drop_key` после последней копии) и тестам (`tests/worker/test_runner_rename.py`: теги переехали; остаются на старом ключе, пока не переименована последняя копия) — теги переезжают; записи CLAUDE.md и PROGRESS.md исправлены.
- **Обложка своим файлом/по ссылке и через то же задание `artwork`** — A03 → R11: выбранный вариант из сети всё равно надо поставить в песню, и тем же диалогом удобно поставить свою.

- **Одна миграция схемы V5** с колонками `library.match_key` (+индекс, бэкфилл SQL-функцией `karaoke_match_key`), `jobs.position`, `jobs.start_at`. Одна миграция в одном таске, чтобы параллельные таски не делили `user_version`.
- **Фон и обложка — одно задание `artwork`** с `kind: cover|background`. Видео живёт отдельно, но публикация устроена так же, как в `publish_video`: меняется одна строка заголовка, прежняя версия уходит в корзину. Картинку по ссылке качает web при постановке (как `cover_url` у generate), поэтому у задания всегда есть файл или `remove`.
- **Поиск обложек** идёт из web через `ctx.http`. iTunes Search API (`artworkUrl100` → `1000x1000bb`), Deezer `search` (`album.cover_xl`), MusicBrainz `release` + Cover Art Archive (`front-500`, превью `front-250`). MusicBrainz требует `User-Agent` `karaoke-services/1.0`. Нужен ключ: нет ни у одного из трёх.
- **Массовые операции** — отдельные эндпоинты с ответом по песням. Опрос песен по одной с клиента дал бы 1000 запросов и не давал бы атомарного итога.
- **Проверка библиотеки и зеркало** — задания воркера без GPU: долгая работа с SMB не должна держать web. Результат проверки — файл `reports/libcheck.json` через `DataPaths`.
- **Расхождение копий** определяется по набору файлов и размерам (`Storage.sizes`), а не по mtime: копирование mtime не сохраняет.
- **Кодировку исправляет web** синхронно (`POST /api/songs/{id}/encoding`), так же как «Редактор нот» пишет `.txt`: старая версия в корзину, `write_atomic`, файл в UTF-8 без BOM.
- **Звук по ссылке** — задание `audio` без GPU. Ссылка берётся только из `#VIDEO` (YouTube, usdb `v=`), потому что под это видео размечены ноты. Поиск «по названию» дал бы рассинхрон, и его нет.
- **Зеркало** запускает воркер: раз в `MIRROR_EVERY_S = 1800` для каждого включённого зеркала без активного `mirror`. Сравнение идёт по индексу (`match_key`) после пересканирования обоих хранилищ тем же кодом, что `rescan`.
- **Очередь**: `start_at` и `position` — колонки, а не `params`: `retry_at` уже занят ожиданием хранилища.
- **Уведомления** шлёт воркер в `runner.run_job` после конечного состояния, с коротким таймаутом и без исключений наружу. Браузерные показывает `app.js` по изменению состояний в опросе `/api/jobs`.
- **Синтезатор ноты** — общий модуль Web Audio для редактора и прогона. Звук без микрофона браузер даёт и по http.
- **Резервная копия** — JSON с `format: "karaoke-services-settings"`, `version: 1`. Секреты не выгружаются по построению: только поля из явного списка, тест проверяет отсутствие `secret/token/password` в выгрузке.
- **Новые экраны** («Песни» в режиме выбора, «Проверка», «Прогон», очередь с порядком и временем, диалог обложки) сначала показываются макетом: так договорились — крупные изменения вида согласовываются.

## Вне рамок

| Требование | Почему не сейчас |
|---|---|
| R13, R14 — плейлисты | пользователь: «Пока что не добавляй плейлисты» |
| R38 — микрофон | пользователь: «Думаю можно обойтись без микрофона»; вместо — G02 |
| HTTPS для веба | браузерные уведомления по http с других устройств не работают; основной канал — Telegram (ответ брифинга 2) |
| Поиск звука «по названию» | рассинхрон с нотами; звук только по ссылке `#VIDEO` или из копии |
| Зеркало в обе стороны, удаление в цели | ответ брифинга 4: только добавляет и обновляет |
