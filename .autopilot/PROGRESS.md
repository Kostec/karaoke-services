# karaoke-services — что осталось

Последняя сборка: `.autopilot/2026-10-27-library-tools/` — баги страницы песни и тегов, фон и обложка из сети, массовые действия, проверка библиотеки, зеркало хранилища, подсветка и звук нот в редакторе, ночная очередь, уведомления, «Прогон», резервная копия настроек.

## Договорились — не пересматривать

- Вкладки «Новая песня» в меню и кнопки «+ Новая песня» в «Очереди» нет — только плавающая «+», сразу в форму
- Свои теги — в базе сервиса по «исполнитель — название», файлы песни не меняются; палитра из 8 цветов, по умолчанию синий
- Крупные изменения вида — сначала макет и согласование («Макет ок, собирай» — `.autopilot/2026-10-27-library-tools/mockup.html`)
- Плейлисты (.upl) не делаем: «Пока что не добавляй плейлисты» (R13, R14)
- Микрофона нет: «Думаю можно обойтись без микрофона» — вместо него «проиграть ноту» в редакторе (R38, G02)
- Сервис открывают с ПК, Pi и телефона по http — HTTPS не поднимаем; основной канал уведомлений — Telegram
- Зеркало само ничего не удаляет: только добавляет и заменяет изменённые, «только в цели» — список с «Убрать в корзину» (R42i)
- Звук песни берётся только по ссылке `#VIDEO` или из копии — поиск «по названию» дал бы рассинхрон с нотами

## Не доделано

- Экраны этой сборки вживую в браузере не проверялись (баннер «хранилище недоступно», «Файл недоступен», режим выбора, «Проверка», «Прогон», карточки «Настроек», подсветка нот) — G01 и ручная приёмка экранов
- Генерация, минусовка и пакетная генерация по ссылке после сборки не запускались (нужен worker с GPU)

## Известные баги

- Очередь показывает 50 последних заданий: после массовой минусовки первые ожидающие не видны, номера мест неверны
- Сохранённый токен Telegram-бота нельзя стереть (только заменить) — `api_settings.put_telegram`
- `/api/settings/telegram/test` без `WEB_PASSWORD` шлёт тестовое сообщение в любой chat id
- `telegram._HideBotPath` маскирует только строковые аргументы лога
- Загрузка настроек применяется не одной транзакцией; смена chat id Telegram не видна в предпросмотре; плохой локальный путь отклоняет весь файл общим текстом
- Правила проверки хранилища продублированы в `core/backup.py` и `web/app/api_targets.py`
- Картинка по ссылке может редиректом увести запрос в домашнюю сеть (проверяется только исходный адрес)
- Зеркало: папка, отличная только регистром, на Google Диске даст две папки
- 503 от действия гасит пункты «…» только при следующем опросе (до 15 с)
- «Проверка»: «Найти обложку…» не помечает строку; пометки «Исправлено» живут, пока открыта страница; двойное нажатие «Проверить»/«Синхронизировать» может поставить два задания
- «Зеркала»: подтверждение «Убрать в корзину» не называет песню и хранилище
- Задание `artwork` «убрать» без обложки/фона ставится и ничего не меняет
- Звук по `#VIDEO` для `.txt` вида `song.txt` получит имя `song.mp3`
- `Jobs.schedule` у идущего задания с прошедшим временем отвечает «Время уже прошло» вместо «можно только ожидающее»
- За обратным прокси без `Host`/`X-Forwarded-Host` все изменяющие запросы получат 403
- «Прогон»: певцы P3+ не обрабатываются; `AudioContext` синтезатора не закрывается
