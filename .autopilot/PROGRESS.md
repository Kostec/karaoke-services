# karaoke-services — что осталось

Последняя сборка: `.autopilot/2026-10-26-songs-ui-ux/` — плавающая «+», меню «…» в «Песнях», страница песни с плеерами и сведениями, свои цветные теги с фильтром.

## Договорились — не пересматривать

- Вкладки «Новая песня» в меню и кнопки «+ Новая песня» в «Очереди» нет — только плавающая «+», сразу в форму (ответ на брифинге «Согласен со всеми», R02/R04)
- Свои теги — в базе сервиса по «исполнитель — название», файлы песни не меняются; палитра из 8 цветов, по умолчанию синий (R15/R16)
- Дизайн экранов согласован с пользователем по макету `.autopilot/2026-10-26-songs-ui-ux/mockup.html` («Макет ок, собирай», G01) — крупные изменения вида снова согласовывать

## Не доделано

- Перенос своих тегов при смене исполнителя/названия песни — вне рамок: тег вешается заново
- Добавление/замена фонового изображения — вне рамок, фон только показывается

## Известные баги

- Видео .avi на странице песни: браузер его не проигрывает, а под плеером написано «Файл недоступен», хотя файл есть (R11, слепая приёмка)
- Свои теги в списке: зоны нажатия 44px соседних тегов перекрываются при переносе на вторую строку — касание у края может включить фильтр по соседнему тегу
- Страница песни: после «Теги…», копирования или готового задания перерисовывается — играющий плеер останавливается, раскрытый текст сворачивается
- Страница песни: плееры после перерисовок не освобождаются, пока открыта вкладка
- `POST /api/tags` с пустым `color` создаёт синий тег вместо 400 «Неизвестный цвет»
- Два одновременных создания тега с одним именем: второе — ошибка 500 вместо «Такой тег уже есть»
- «Хранилища» на странице песни перебирают весь индекс песен (`Library.copies`) — на тысячах песен медленнее
- Страница песни не гасит пункты «…», если хранилище отвалилось после открытия
- Баннер «хранилище недоступно» и «Файл недоступен» на странице песни вживую не проверялись
