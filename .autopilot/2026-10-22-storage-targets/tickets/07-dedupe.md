## Что должно заработать

Одинаковое правило, написанное в нескольких тасках по-своему, — в одном месте. Поведение и публичные сигнатуры (`interfaces.md`) не меняются; все существующие тесты остаются зелёными без ослабления утверждений.

1. **Выбор и кэш хранилища.** `AppContext` и `JobContext` сейчас каждый по-своему реализуют `target_of`, `storage(target_id)` с кэшем (разный ключ кэша), `reset_storage`, `local_storage`, `migrate_targets`. Правило переезжает в один класс/модуль `karaoke_core` (например, `karaoke_core.storage.registry`), контексты его зовут. Сообщение «хранилище удалено из настроек» — с заглавной буквы и с id/именем хранилища.
2. **Сетевые хранилища.** Общие помощники (`UploadOnClose`, `download_temp`, `ListingCache`, `MAX_FILE_BYTES`) и общий перевод `HttpError`/`OSError` → `StorageError`/`StorageNotFound` — в отдельном модуле (например, `storage/_net.py`); в `webdav.py`/`gdrive.py` остаются только свои протоколы и свои статусы.
3. **API хранилищ.** Разбор/проверка пути (нет `..`, `.`, `:`) в `api_targets.py` — одна функция для всех трёх мест; правило удаления (local, основная, нет такого) живёт только в `Settings.delete_target`, API лишь сопоставляет его ошибки со статусами 400/404/409; имя хранилища по умолчанию строит одна функция в `db` (её же зовёт миграция); `BROWSE_ROOTS_MOUNT` не дублирует `BROWSE_ROOTS`.
4. **Копирование.** «Перезапустить» задание `copy` ставит его через `Jobs.enqueue_copy` (правило дубля), а не `jobs.enqueue` напрямую; `retry_at` пишется тем же форматом, что `db.now()` (общий помощник в `db`). Тест на restart при уже активной такой же копии.
5. **Поиск песни по id.** `Library.find(song_id)` не перебирает всю таблицу с sha1 на каждый запрос: колонка `song_id` в `library` (миграция схемы V3, заполнение для существующих строк, индекс) или иной поиск по индексу. Тест.
6. **Панель «Текст».** Статус строки — отдельной колонкой слева рядом с номером (спека §15 «номер/статус — отдельной колонкой grid»), перенос текста — с отступом под текстом; на узком экране — как сейчас.
