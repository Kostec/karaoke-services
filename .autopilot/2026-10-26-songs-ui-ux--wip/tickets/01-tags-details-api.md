## Что должно заработать

Сервер хранит свои теги пользователя (имя, цвет из палитры) и связи «тег — песня» по ключу «исполнитель — название»; отдаёт их в списке песен и через REST тегов. Для страницы песни есть `GET /api/songs/{id}/details` (заголовки, что есть у песни — аудио, минус, вокал, видео, обложка, фон, mid, — файлы с размерами, копии в других хранилищах, ссылка usdb) и `GET /api/songs/{id}/file?name=` — любой файл папки песни с Range, для плееров и скачивания. Интерфейс в этом таске не меняется.

## Из брифа, дословно

> «возможно стоит дать пользователю возможность добавлять свои (другим цветом)»
> «увидеть всю информацию по ней:   автор, исполнитель, текст, видео, что для этой песни есть (например, минус, вокал, видео, дать возможность их проиграть, фоновое изображение и т.д.) и прочая информация»
> Дополнения: «3 — свои теги в базе сервиса по «исполнитель — название», фильтр по ним в «Песнях»; 4 — палитра цветов для своих тегов, один цвет по умолчанию»
