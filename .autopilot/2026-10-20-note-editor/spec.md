# Спецификация: редактор нот

## Задача

Сгенерированная песня почти всегда требует доводки: слог стоит не на той ноте, строка начинается раньше голоса, нота короче, чем тянет певец, лишняя нота на вдохе, нет ноты там, где поют. Сейчас можно поправить только буквы слогов и границы строк — время, длительность, высоту и сам набор нот не тронуть, а музыку слышно только отрывком строки. Чтобы довести песню, приходится брать сторонний редактор UltraStar на ПК.

## Решение

В карточке песни кнопка «Править слова» заменяется на **«Редактор нот»**. Он открывается почти на весь экран, раскладка — как в согласованном макете (`design.html` в этой папке, «Ок» пользователя 2026-10-20):

- сверху — проигрывание (▶/пауза, «▶ строка», время, скорость, «Следовать»), масштаб, отстукивание, «Выделить всё» и действия с выбранными нотами;
- в центре — таймлайн: линейка времени, волна громкости трека, ноты полосами по высоте, под ними дорожка слогов, пунктир границ строк, красный курсор проигрывания;
- справа — сворачиваемая панель текста по строкам: правка строки как обычного текста раскладывает слоги по нотам строки; клик по строке — переход к её первой ноте;
- снизу — подсказка по основным жестам; `?` — все сочетания клавиш.

Сохранение пишет `.txt` песни, прежняя версия уходит в корзину — как у нынешних редакторов.

## Решения по реализации

1. **Фронт без сборки, как сейчас.** Новый редактор — ES-модули в `web/static/js/editors/`, регистрируется в `editors/index.js` под тем же id `notes` с подписью «Редактор нот». Прежний `lines-editor.js` удаляется; чистые функции из `lines.js` переезжают в новую модель (его тесты — туда же). Почему: одна кнопка вместо двух похожих (ответ пользователя «Заменить новым»).
2. **Модель — чистый модуль без DOM** (под node-тесты): плоский список нот `{id, type, start, length, pitch, text, ls}` (`ls` — нота начинает строку) + `gap`, `bpm`. Все операции возвращают новое состояние; история отмены — стек снимков в модели. Почему: правило проекта — чистая логика отдельно ради node-тестов; плоский список проще для перетаскивания поперёк строк, строки выводятся из `ls`.
3. **Порядок нот** — по `start`. Если после перетаскивания нота обогнала соседнюю, порядок и строки пересчитываются по времени (слог едет вместе со своей нотой). Флаг `ls` остаётся у своей ноты; у первой ноты песни он всегда истинен.
4. **Бит разрыва строки** при сохранении: прежний, если он всё ещё между концом предыдущей ноты и началом следующей, иначе — конец предыдущей ноты.
5. **Сдвиг раньше бита 0** (выделено всё и двигаем влево): все ноты сдвигаются так, чтобы первая была на бите 0, а `gap` уменьшается на столько же миллисекунд (`бит × 60000 / (BPM × 4)`). Время звучания нот не меняется. Почему: UltraSinger ставит первую ноту на бит 0, иначе песню нельзя сдвинуть раньше (G02). `gap` < 0 не допускается — сообщение «Раньше начала трека сдвигать некуда: #GAP не может быть меньше 0». *Уточнено при сборке (таск 02):* правило действует для любого сдвига левее бита 0 (перетаскивание, растяжение за левый край, новая нота, отстукивание), не только при «выделить всё» — время звучания остальных нот сохраняется.
6. **Слоги из строки текста** — свой простой делитель: слог на каждую гласную (рус. `аеёиоуыэюя`, лат. `aeiouy`; *уточнено при сборке:* латинские гласные подряд — один слог, слово без гласных приклеивается к соседнему), одна согласная между гласными уходит в следующий слог, `й ь ъ` остаются с предыдущим, `|` — принудительная граница; пробел перед словом — в начале его первого слога (формат .txt). Почему: словари переносов есть только в образе worker, а точность «по гласным» достаточна — слоги потом правятся по одному.
7. **Звук** — `<audio>` с `GET /api/songs/{id}/audio` (Range уже есть), `playbackRate` с `preservesPitch`. Позиция курсора — из `audio.currentTime` в `requestAnimationFrame`.
8. **Волна** — `fetch` аудио → `AudioContext.decodeAudioData` → пики (макс. модуля) по ~10 мс → буфер отпускается. Рисуется в `<canvas>` под текущий масштаб, только видимая часть (ширина canvas ≤ ширины области). Ошибка или файл > 60 МБ — полоса скрыта с подписью «Волна недоступна». Почему: без волны «расстановка по таймлайну» — на слух вслепую.
9. **Отрисовка таймлайна** — DOM-элементы нот и слогов (а не canvas), чтобы работали фокус, подсказки и клавиатура; при перетаскивании меняются только затронутые элементы. Должно быть плавно на песне в 1500 нот.
10. **Клавиши** — по `KeyboardEvent.code` (работают в русской раскладке). Сочетания — как в справке макета. Пока фокус в поле ввода, сочетания редактора не срабатывают (кроме `Esc` в поле слога).
11. **Окно** — общий `openShell` получает вариант «широкое окно» (почти весь экран на ПК, весь экран на телефоне); подтверждение при закрытии и уходе со страницы — существующее.
12. **Сервер: `GET /api/songs/{id}/notes`** — как сейчас, плюс у каждой ноты `id` — её порядковый номер в исходном файле (0…N-1).
13. **Сервер: `PUT /api/songs/{id}/notes`** принимает новые тайминги, высоты, типы, добавленные (`id: null`) и удалённые ноты, границы строк и `gap`. Правила:
    - если правок нет — файл не трогается (как сейчас);
    - ноты, у которых поля не менялись, и все прочие строки файла пишутся байт в байт; изменённые и новые — в каноническом виде с переводом строки файла; кодировка и BOM сохраняются;
    - неразобранные строки внутри тела остаются перед той нотой, перед которой стояли (если она удалена — перед следующей уцелевшей); всё после `E` — как было;
    - `#GAP` переписывается только если `gap` изменился (целое — без дробной части);
    - заголовки кроме `#GAP` не меняются; дуэт и `#RELATIVE` → 409 с прежним текстом; нет `#BPM` → 409 «В песне нет #BPM — редактор только для просмотра».
14. **Проверки PUT** (400, текст по-русски, поле `detail`): хотя бы одна нота; `type` из `: * F R G`; `start ≥ 0`, `length ≥ 1`, `pitch` в −40…100; текст без переводов строк; пустая строка тела (без нот) пропускается; ноты по возрастанию `start` без перекрытия (`start ≥ конец предыдущей`) — «Ноты перекрываются: строка K, слог «…»»; бит разрыва между концом предыдущей ноты и началом следующей; `id` существует и не повторяется; `gap ≥ 0`. Клиент проверяет то же до отправки.
15. **Пустой слог** допустим (ноту можно сохранить без текста); на дорожке он виден как `∅` красным.

## Границы и швы

| Модуль | Владеет | Выставляет | Прячет |
|---|---|---|---|
| `web/app/notes.py` | перевод нот ⇄ модель `.txt` | `notes_payload(song) -> dict` (у нот `id`); `apply_notes(song, body: NotesIn) -> None` (ApiError 400/409); `NotesIn` (`gap: float \| None`, `lines[].notes[].id: int \| None`) | сопоставление нот по `id`, перенос неразобранных строк, сохранение байт неизменённого |
| `editors/notes-model.js` | состояние редактора и все правки | `fromPayload(data) -> State`; `toPayload(state) -> body PUT`; `lines(state) -> [[note]]`; операции `move(state, ids, dBeat, dPitch)`, `resize(state, id, edge, dBeat)`, `addNote(state, {start, pitch, length})`, `deleteNotes(state, ids)`, `setText(state, id, text)`, `setLineText(state, li, text)`, `addNotesToLine(state, li, k)`, `shiftText(state, id, dir)`, `splitNote(state, id)`, `joinNext(state, id)`, `startLine(state, id)`, `mergeLineAt(state, id)`, `toggleGold(state, ids)`, `retime(state, id, start, length)`; `overlaps(state) -> Set<id>`; `validate(state) -> null \| {message, id}`; `isDirty(state, original)`; история `history(): {push, undo, redo, canUndo, canRedo}`; `beatToMs`, `msToBeat` | нормализацию порядка и `gap`, вычисление битов разрыва |
| `editors/syllables.js` | деление строки на слоги | `toSyllables(text) -> string[]` | правила гласных/согласных |
| `editors/notes-editor.js` (+ при надобности `editors/timeline.js`, `editors/waveform.js`) | экран редактора: таймлайн, панель текста, транспорт, отстукивание, клавиши | `openNotesEditor(song, {reload})` | DOM, мышь, аудио, волна |

**Швы тестов:** `PUT/GET /api/songs/{id}/notes` через `TestClient` (`tests/api/test_songs.py`) и чистые функции `notes-model.js` / `syllables.js` (`node --test tests/frontend/`). UI проверяется вручную в браузере.

## Дополнение 2026-10-20: сдвиг текста по нотам (G03)

Заменяет прежнее поведение историй 24 («⇠ текст / текст ⇢» только внутри строки и только при свободной ноте в конце).

| # | Метка | История | Приёмка |
|---|-------|---------|---------|
| 36 | G03 | Как владелец, я выбираю, докуда сдвигать текст: **слово · строка · до конца песни** (переключатель рядом с «⇠ текст / текст ⇢», запоминается в браузере, по умолчанию «строка») | переключатель виден, выбор переживает повторное открытие |
| 37 | G03 | …жму «текст ⇢» (`Alt+→`) на выбранной ноте — её слог и все следующие в пределах выбранной области уезжают на одну ноту вправо, на выбранной остаётся «~» | текст не теряется никогда: последний слог области, которому не хватило ноты, приклеивается к последней ноте области (если это «~» — просто исчезает); ноты за областью не трогаются |
| 38 | G03 | …жму «⇠ текст» (`Alt+←`) — слог выбранной ноты приклеивается к предыдущей ноте (если там «~» — заменяет его), все следующие в пределах области подтягиваются на одну ноту влево, последняя нота области получает «~» | для «слово» и «строка» предыдущая нота — внутри области; если выбрана первая нота области — сообщение «Левее в этом слове/строке нот нет» |
| 39 | G03 | …сдвигаю несколько раз подряд, и каждый сдвиг — один шаг отмены | `Ctrl+Z` возвращает ровно один сдвиг |
| 40 | G03 | …перетаскиваю слог мышью по дорожке слогов на другую ноту — весь текст области с этого места сдвигается туда же (на столько нот, на сколько перетащил), с подсказкой во время перетаскивания «текст ⇢ на K нот» | один шаг отмены; короткий клик по слогу по-прежнему выделяет ноту, двойной — правка |

**Область:** *слово* — ноты одного слова в строке (граница слова — пробел в начале слога или в конце предыдущего, начало строки); *строка* — до конца строки; *песня* — до последней ноты песни, через границы строк (сами границы строк и ноты не двигаются, двигается только текст).

**Модель:** одна функция `shiftTextBy(state, id, k, scope)` (k — число нот, знак — направление; `scope` — `'word'|'line'|'song'`); прежняя `shiftText(state, id, dir)` = `shiftTextBy(state, id, dir, 'line')` с новым поведением (без отказа при занятой последней ноте). Чистая, с node-тестами; формат UltraSinger (пробел в конце слога, «~» с пробелами) учитывается.

**Вне рамок:** G04 — правка строки в панели справа остаётся как есть (пользователь: «Пока что оставь как есть»).
