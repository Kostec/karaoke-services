# 0020. По ссылке качается только видеодорожка, сортировкой `res:H,vcodec:h264`

## Контекст

Видео должно играть на Pi. Заказчик выбрал «по умолчанию 720p, при отсутствии — ближайшее» и захотел выбирать качество сам.

## Решение

yt-dlp качает только видеодорожку и выбирает её сортировкой по близости к заданной высоте с предпочтением H.264 и mp4; «лучшее» — без ограничения высоты. Результат всегда `.mp4`. Высота выбирается в интерфейсе, по умолчанию 720.

## Почему

- **Видео со звуком** отвергнуто: звук у песни уже свой, а лишняя дорожка увеличивает файл и может помешать плееру.
- **Фильтр `height<=H`** отвергнут: при отсутствии роликов ниже нужной высоты он даёт ошибку вместо ближайшего сверху, что противоречит словам заказчика.
- **Перекодирование в H.264 после скачивания** отвергнуто: в образе нет NVENC, на CPU это долго; сортировка почти всегда находит H.264 сразу.
- **Фиксированное 720p без выбора** отвергнуто: заказчик прямо попросил выбор.

## Последствия

- Если у источника нет H.264 нужной высоты, придёт VP9/AV1 — на Pi такой ролик может тормозить или не играть, и это видно только в плеере.
- Поведение зависит от сортировки yt-dlp; смена её семантики в новой версии незаметно поменяет выбор.
- Видео без раздельных дорожек (часть сайтов) при «только видео» не скачается — задание упадёт с русской ошибкой.
