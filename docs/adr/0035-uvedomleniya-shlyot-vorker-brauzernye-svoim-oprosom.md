# 0035. Уведомления шлёт воркер; браузерные — собственным опросом; Telegram — основной канал (D01)

## Контекст

План (D01) предполагал, что браузерные уведомления будут жить в общем опросе статуса `app.js`. Но этот опрос не работает при скрытой вкладке, а уведомления нужны именно тогда. К тому же сервис открывают с Pi и телефона по http, где браузер не разрешает уведомления.

## Решение

Telegram-сообщение отправляет воркер в `runner.run_job` после конечного состояния задания (и сводкой «очередь опустела»), с коротким таймаутом и без исключений наружу. Браузерные уведомления показывает отдельный `notify.js`, который сам опрашивает задания раз в 15 с. При `!isSecureContext` переключатель погашен с пояснением; основной канал — Telegram.

## Почему

- **Опрос в `app.js`** отвергнут: при скрытой вкладке он замирает, и уведомление об окончании ночного задания пришло бы с опозданием или вообще не пришло.
- **Telegram из web** отвергнут: web не знает момента завершения, он только читает БД; воркер этот момент и создаёт.
- **HTTPS ради браузерных уведомлений** вынесен за рамки: сертификат для домашней сети — отдельная задача.
- **Web Push** отвергнут: нужны сервис-воркер, VAPID-ключи и тот же HTTPS.

## Последствия

- Без открытой вкладки браузерных уведомлений нет вообще; на телефоне и Pi по http — только Telegram.
- Telegram зависит от интернета и доступности api.telegram.org из контейнера; сбой пишется в лог задания, токен из строки лога вырезается.
- Два независимых опроса заданий (`app.js` и `notify.js`) нагружают БД сильнее.
- Токен бота хранится в настройках и не возвращается API; потерянный токен вводят заново.
