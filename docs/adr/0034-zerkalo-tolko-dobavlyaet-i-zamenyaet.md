# 0034. Зеркало только добавляет и заменяет; первый прогон только добавляет

## Контекст

Пользователь хочет, чтобы одно хранилище само поддерживалось копией другого. Копии после правок расходятся (ADR 0028), и зеркало должно их выравнивать, не приводя к потере данных.

## Решение

Зеркало работает в одну сторону «откуда → куда» и ничего не удаляет. Песни нет в цели — `copy` без замены; изменена в источнике — `copy` с заменой, при другой папке с `replace_rel_dir`, прежняя уходит в корзину цели. Первый прогон только добавляет и ничего не заменяет. Песни, которых нет в источнике, показаны списком с кнопкой «Убрать в корзину» и подтверждением. Сопоставление идёт по `match_key`; если в источнике несколько папок с одним ключом, копией считается та папка цели, чей `rel_dir` совпадает с папкой источника без учёта регистра, а остальные папки источника идут по ветке «нет в цели».

## Почему

- **Настоящая синхронизация с удалением** отвергнута: пользователь отказал на брифинге; а сбой чтения источника (шара пропала посреди сканирования) выглядел бы как «песен больше нет» и стирал бы цель.
- **Двустороннее зеркало** отвергнуто: нужно разрешение конфликтов, от которого ADR 0024 и 0028 отказались.
- **Заменять уже в первый прогон** отвергнуто: в цели могут быть свежие правки, которых нет в источнике, и прогон затёр бы их по одному отличию размеров.
- **Выбирать копию в цели только по `match_key`** отвергнуто: две папки источника с одним ключом сматчились бы на одну папку цели, и вторая заменила бы первую (найдено ревью, F1).

## Последствия

- В цели копятся песни, удалённые в источнике, пока пользователь не уберёт их кнопкой.
- Песня, переименованная в источнике, оставляет в цели прежнюю папку: будут две.
- Правка в цели молча затирается при следующем изменении в источнике (старая версия лежит в корзине цели, откат — вручную).
- Первый прогон не выровняет уже разошедшиеся копии; для этого нужна «Проверка библиотеки».
