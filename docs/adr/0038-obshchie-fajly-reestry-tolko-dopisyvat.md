# 0038. Файлы-реестры, которые пишут несколько тасков, правятся только дописыванием своего блока

## Контекст

Двенадцать тасков шли параллельно. Часть файлов (`api.js`, `app.css`, `index.html`, `app.js`, `main.py`, `handlers.py`, `progress.py`, `queue.js::TYPE_LABEL`, `api_jobs.py::BUSY_TYPES`/`restart`) нужна почти каждому: туда вносится строка подключения нового модуля.

## Решение

Такие файлы вынесены из зон ответственности тасков. Исполнители правят их только инструментом Edit, дописывая свой блок с комментарием-меткой своего раздела; переписывать файл целиком и переставлять чужое нельзя. Всё остальное — в новых модулях (`worker/karaoke_worker/<тип>.py`, `web/app/api_<что>.py`, `web/static/js/<что>.js`).

## Почему

- **Закрепить каждый реестр за одним таском** отвергнуто: остальные ждали бы его, и параллельные волны превратились бы в последовательные.
- **Автогенерация реестров сканированием папки модулей** отвергнута: теряется явная картина подключений в `main.py` и `HANDLERS`, а фронт без сборки не умеет перечислять файлы.
- **Править реестры свободно и разруливать конфликты при слиянии** отвергнуто: большие файлы, которые пишут все, сливаются плохо, и чужая строка легко пропадает.

## Последствия

- Реестры растут блоками, их порядок отражает порядок сдачи тасков, а не логику.
- Повторяющиеся правила расползаются по реестрам, пока кто-то не вынесет их в core: так появились три копии «активное задание зеркала» и дубли `plural`/`showModal`, исправленные ревью F1.
- Метка в комментарии — единственная защита: ревью обязано проверять, что блок соседа не задет.
