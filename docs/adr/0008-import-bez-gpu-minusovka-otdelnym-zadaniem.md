# 0008. Задание `import` не требует GPU, минусовка — отдельным заданием

## Контекст

Готовой песне из сборника не нужны whisper и выравнивание, но часто нужна минусовка через demucs, а он работает на GPU. Воркер без GPU берёт только задания, которым видеокарта не нужна.

## Решение

`import` — задание с `needs_gpu=False`: загрузка звука (yt-dlp), ffmpeg, сборка папки, `finalize` и выкладка. Если отмечено «Сделать минусовку», после успешной выкладки ставится обычное задание `instrumental` с `parent_id` импорта.

## Почему

- **Минусовка внутри задания `import`** отвергнута. Тогда GPU требовал бы весь импорт, и при недоступной карте песня, которую можно выложить за минуту, ждала бы в очереди. Сбой demucs валил бы весь импорт вместе с уже скачанным звуком, а «Выложить повторно» и «Перезапустить» пришлось бы учить продолжать с середины.
- **Импорт как разновидность `generate`** с пропуском шагов UltraSinger отвергнут: `generate` всегда требует GPU и строится вокруг вызова UltraSinger, а условие «здесь не генерируем» размазалось бы по всему обработчику.
- **Не ставить минусовку автоматически, оставить только кнопку в «Песнях»** отвергнуто: пользователь прямо попросил опцию при импорте, потому что в сборниках часто есть только «плюс».

## Последствия

- Один импорт порождает два задания: пользователь видит в очереди «Импорт», а следом «Минусовку», и отменять их нужно по отдельности.
- Между выкладкой и минусовкой песня уже лежит в папке результата без `[Instrumental]`. Если минусовка упадёт, песня так и останется выложенной без неё. Это ожидаемое состояние, а не повод для отката.
- `parent_id` теперь используется не только для `publish`: код очереди и интерфейса должен учитывать задания, порождённые другими заданиями.
- yt-dlp и deno становятся частью образа worker, которую проверяет `selfcheck`. Поломку загрузки с YouTube проверка установки не поймает — она видна только на реальном импорте.
