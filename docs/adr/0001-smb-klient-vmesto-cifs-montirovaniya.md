# 0001. Запись на шару Pi через SMB-клиент внутри контейнера

## Контекст

Бриф допускал два способа выложить песню на Samba-шару Pi: CIFS-монтирование в compose или Windows-диск. Пользователь потом добавил, что папку результата можно менять из веба. Имя `pi` внутри контейнеров не резолвится, а шара в Windows подключена без буквы диска.

## Решение

Web и worker пишут на шару сами, через SMB-клиент `smbprotocol` в Python. Монтирования нет. Код работает с хранилищем через интерфейс `Storage`, у которого две реализации: `SmbStorage` для шары и `LocalStorage` для папки, примонтированной из `LOCAL_OUTPUT_ROOT`. Адрес шары — IP из `.env`, по умолчанию `192.168.0.129`.

## Почему

- **CIFS-том в compose** отвергнут. Цель монтирования задаётся при старте контейнера, поэтому из веба её не сменить, а это требование G01. Монтирует Docker-демон: если Pi выключен, контейнер не стартует, а когда Pi перезагружается, монтирование отваливается и задания падают без внятной причины. Это первая находка состязательного прохода.
- **Сетевой диск Windows (`K:`)** отвергнут. Docker Desktop не передаёт в контейнер сетевые диски, они видны только в сессии пользователя. Bind-mount UNC-пути тоже не работает. Буквы диска у шары сейчас вообще нет.
- **Монтирование изнутри контейнера** (`mount -t cifs` в entrypoint) отвергнуто. Для него нужен privileged или `CAP_SYS_ADMIN`, а при смене цели — перемонтирование под работающими процессами.

## Последствия

- Цель меняется на лету без перезапуска и без привилегий. Если шара недоступна, это видно в интерфейсе как баннер с причиной, и контейнер при этом работает.
- Атомарность, повторы, перенос в корзину (скопировать → сверить размеры → удалить) и сканирование песен пишем сами, а не получаем от файловой системы. Поэтому список песен берётся из индекса в БД: прямой обход шары по SMB при сотнях песен медленный.
- UltraSinger не умеет писать на шару, поэтому результат всегда сначала собирается в томе и только потом выкладывается отдельным шагом.
- Если IP Pi сменится, придётся поменять `.env` или настройки в вебе: mDNS-имя внутри контейнера не работает.
- Пароль Samba, введённый в вебе, хранится в томе `data` открытым текстом.
