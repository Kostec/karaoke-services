# 0011. Исходящий HTTP — стандартная библиотека в общем модуле `core`

## Контекст

Web впервые ходит в интернет: в LRCLIB, в usdb с сессией по cookie, за zip по ссылке и в API GitHub. В образе web нет HTTP-клиента, а тесты API не должны ходить в сеть.

## Решение

Все исходящие запросы идут через `core/karaoke_core/http.py`, написанный на `urllib.request` и `http.cookiejar`. Модуль задаёт таймаут и предел размера ответа, переводит ошибки в `HttpError` с русским текстом, а `Http.session()` даёт отдельную cookie-банку. `create_app(http=…)` принимает фейк, и все тесты LRCLIB, usdb и ссылок идут через него.

## Почему

- **httpx или requests** отвергнуты. Нужны только простые GET и POST без асинхронности и пулов. Новая зависимость означает пересборку образов web и tests и ещё одну библиотеку, за версиями которой надо следить. Подменять в тестах всё равно удобнее свой интерфейс, чем транспорт библиотеки.
- **Вызывать urllib прямо в `lyrics.py`, `usdb.py` и коде импорта** отвергнуто: предел размера, таймауты и перевод ошибок пришлось бы повторять в каждом клиенте, а тестам — подменять модуль стандартной библиотеки.
- **Положить модуль в `web`, а не в `core`,** отвергнуто: скачивание по ссылке и запросы к GitHub могут понадобиться и worker, а `core` и так общий пакет обоих контейнеров.

## Последствия

- `urllib` синхронный: каждый запрос держит поток обработчика FastAPI вплоть до таймаута. Если usdb тормозит, несколько одновременных поисков заметно займут пул потоков.
- Повторы запросов, HTTP/2, прокси и тонкости cookie (`SameSite`, домены) остаются на нас. Если они понадобятся, придётся дописывать модуль или всё же переходить на библиотеку — но менять тогда нужно будет только `http.py`.
- Фейк `Http` — единственная граница с сетью в тестах, поэтому поведение настоящих серверов (редиректы, кодировки ответов) тесты не проверяют.
