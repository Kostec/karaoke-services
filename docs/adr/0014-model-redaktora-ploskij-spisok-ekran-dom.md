# 0014. Модель редактора нот — плоский список в чистом модуле, экран — DOM

## Контекст

Редактору нот нужны перетаскивание нот поперёк строк, отмена до 200 шагов, проверка перекрытий и клавиатурное управление; фронт собирается без сборщика из ES-модулей, а правило проекта — чистая логика отдельно ради `node --test`. Песня бывает до ~1500 нот.

## Решение

Состояние редактора — `editors/notes-model.js` без DOM: плоский список нот `{id, type, start, length, pitch, text, ls}` по возрастанию `start`, где `ls` — нота начинает строку, плюс `gap` и `bpm`. Строки выводятся из `ls`; у первой ноты он всегда истинен; нота, обогнавшая соседку, переставляется по времени вместе со слогом, а `ls` остаётся при ней. Бит разрыва строки при сохранении — прежний, если он ещё между нотами, иначе конец предыдущей ноты. Все операции возвращают новое состояние, история — стек снимков. Экран (`notes-editor.js` и помощники таймлайна и волны) рисует ноты и слоги DOM-элементами, волну — в `<canvas>` только видимой части; при перетаскивании меняются только затронутые элементы. Новый редактор регистрируется под прежним id `notes` и заменяет `lines-editor.js`.

## Почему

- **Модель строк со вложенными нотами (как в `.txt`)** отвергнута: перетаскивание ноты через границу строки превращалось бы в перенос между массивами с пересчётом обеих строк; в плоском списке это просто смена `start`.
- **Хранить биты разрыва строк явно** отвергнуто: их пришлось бы поправлять при каждом сдвиге соседних нот; вычисление при сохранении проще и всегда согласовано.
- **Изменяемое состояние с журналом обратных операций** отвергнуто: для каждой из ~15 операций нужна обратная, и ошибка в любой ломает отмену; снимки неизменяемых состояний дают отмену бесплатно.
- **Таймлайн целиком на `<canvas>`** отвергнут: фокус, `title`, `aria-label` и клавиатурная навигация по нотам пришлось бы делать заново; DOM даёт их даром, а на 1500 нот при точечном обновлении хватает скорости.
- **Фреймворк (React, Vue) или сборщик** отвергнуты: проект живёт без сборки, и один экран не стоит смены всей фронтовой инфраструктуры.

## Последствия

- Снимки на каждый шаг держат до 200 копий списка нот в памяти — на больших песнях это мегабайты, но приемлемо.
- DOM-отрисовка упирается в число элементов: если песни станут заметно длиннее или появится несколько голосов, может понадобиться виртуализация видимой области.
- Модель покрыта node-тестами, а экран — нет: мышь, звук, волна и отстукивание проверяются только руками в браузере.
- Прежние тесты `lines.js` переехали в модель; любые сторонние правки строк теперь идут только через неё.
