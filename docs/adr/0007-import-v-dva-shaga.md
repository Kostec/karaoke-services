# 0007. Импорт в два шага: разбор во временную папку, затем задание

## Контекст

Исполнитель, название, наличие звука и состав пака становятся известны только после того, как архив скачан и распакован. Пак может содержать десятки песен, и часть из них уже лежит в папке результата.

## Решение

Импорт делится на два запроса. `POST /api/import/inspect` скачивает или принимает файлы, распаковывает их в `imports/<token>/` тома data и возвращает список найденных песен, ничего не ставя в очередь. `POST /api/jobs/import` по токену и номеру песни переносит её файлы в `jobs/<id>/in/` и ставит задание. Разобранное хранится час, потом его удаляет уборка web и worker.

## Почему

- **Один запрос «загрузил — сразу в очередь»** отвергнут. Пользователь не увидел бы, что нашлось, не смог бы поправить исполнителя и название до того, как от них начнут зависеть имя папки и проверка дубля, и не выбрал бы песни из пака. Ошибку «не та песня» пришлось бы исправлять отменой задания или удалением уже выложенной папки.
- **Разбор архива в браузере** (JSZip и т.п.) отвергнут. Для ссылок на zip и GitHub архив всё равно скачивает сервер, а распаковка архива на 500 МБ в памяти телефона ненадёжна. Кроме того, разбор `.txt` с кодировками уже есть в `core` (`ultrastar.decode`), и второй разбор на JS разошёлся бы с ним.
- **Повторная загрузка архива во втором запросе** отвергнута: для пака архив пришлось бы гонять по сети на каждую выбранную песню, а для usdb и ссылок — скачивать заново.
- **Хранить результат разбора в БД** отвергнуто: файлы всё равно нужны на диске, а результат лежит рядом с ними в `meta.json`. Запись в SQLite только добавила бы второе место правды.

## Последствия

- В томе появился третий вид временных данных (`imports/`) со своей уборкой. Если уборка сломается, том будет расти на объём брошенных архивов.
- Между двумя шагами на сервере хранится состояние. Если страница была закрыта дольше часа, пользователь получит «Загрузка устарела, загрузите заново» и загрузит архив ещё раз.
- Токен — единственная связь между шагами. Его формат и срок жизни теперь часть контракта web ↔ фронт, и менять их придётся на обеих сторонах сразу.
- На время импорта на диске лежит до трёх копий песни: архив, распакованные файлы (до 2×`MAX_IMPORT_MB`) и `jobs/<id>/in/`.
