# 0027. «Любая папка ПК» — подпапка одного примонтированного корня `HOST_FOLDERS_ROOT`

## Контекст

Пользователь хочет добавлять хранилищем любую папку ПК, а контейнер видит только то, что примонтировано в `docker-compose.yml`.

## Решение

web и worker монтируют `${HOST_FOLDERS_ROOT:-./output}:/host`; хранилище типа «Папка ПК» — путь внутри `/host` или `/output`, выбранный обзором каталогов (`GET /api/targets/browse`), выйти за корень он не может. Папка вне корня становится доступной сменой `HOST_FOLDERS_ROOT` в `.env` и `up -d`.

## Почему

- **Отдельный том на каждую добавленную папку** отвергнут: веб должен был бы переписывать `docker-compose.yml` и пересоздавать контейнеры из самого себя — доступ к Docker изнутри контейнера и перезапуск собственного процесса.
- **Монтировать по умолчанию весь диск или все диски** отвергнуто: контейнер с вебом получил бы запись во всё содержимое ПК без явного решения пользователя.
- **Ввод произвольного пути строкой** отвергнут: путь вне смонтированного корня внутри контейнера просто не существует, и ошибка была бы непонятной.

## Последствия

- «Любая» — только в пределах одного корня: папка на другом диске требует правки `.env` и перезапуска.
- Корень открыт контейнерам целиком на запись; ошибка в разборе пути — риск для всех файлов внутри него, поэтому проверка выхода за корень обязательна.
- Смена `HOST_FOLDERS_ROOT` после добавления хранилищ молча меняет смысл их путей — сохранённые пути относительны корню.
