# 0028. Правка песни меняет только открытую копию

## Контекст

После ADR 0024 одна песня лежит в нескольких хранилищах, а ноты, видео, минусовка, удаление и корзина раньше знали только одну папку результата.

## Решение

Правка работает с той копией, которую пользователь открыл: задания `instrumental`/`video`, PUT нот, DELETE и корзина берут хранилище по `target_id` строки индекса песни, `restore` — по `target_id` записи корзины. Другие копии не трогаются; выровнять их — «Копировать в…» с заменой. Перегенерация с новым текстом — исключение: она выкладывается как новая песня (локально + основная цель) с заменой в хранилище открытой песни.

## Почему

- **Автоматическое зеркалирование правок во все копии** отвергнуто: копия может быть недоступна, правки разных копий конфликтуют, а их разрешение требует версий и слияния — отдельная задача, вынесенная за рамки.
- **Правка всегда в основной цели** отвергнута: песня, открытая из другого хранилища, менялась бы не там, где пользователь её видит, а при недоступной цели правка была бы невозможна.
- **Одна «главная» копия, остальные только для чтения** отвергнуто: корзина, видео и минусовка перестали бы работать для песен неосновных хранилищ, что обещано требованием R22i.

## Последствия

- Копии расходятся молча: после правки на шаре локальная копия остаётся старой, и интерфейс об этом не предупреждает.
- «Копировать в…» с заменой отправляет прежнюю версию в корзину цели — правка одной копии затирает правку другой без слияния.
- Добавить автосинхронизацию позже значит вводить версии копий и правила конфликтов поверх уже разошедшихся данных.
