# 0030. Обложка и фон — одно задание `artwork`; картинку по ссылке качает web

## Контекст

Видео уже ставится отдельным заданием без GPU (ADR 0019). Теперь нужны ещё фон (`#BACKGROUND`) и обложка (`#COVER`), причём картинка может быть своим файлом, ссылкой или вариантом из iTunes, Deezer и MusicBrainz.

## Решение

Одно задание `artwork` с `kind: cover|background`, без GPU. Публикация устроена как у `publish_video`: меняется одна строка заголовка, прежняя версия `.txt` уходит в корзину, старый файл с другим именем удаляется. Картинку по ссылке скачивает и проверяет web при постановке; у задания всегда есть файл или `remove`.

## Почему

- **Два задания, `cover` и `background`** отвергнуто: различаются они только заголовком и суффиксом имени, а дубль в очереди, перезапуск и выкладку пришлось бы писать и тестировать дважды.
- **Скачивание ссылки в воркере** отвергнуто: ошибка (не картинка, домашняя сеть, слишком большой файл) всплыла бы уже в очереди, а не у поля формы, и перезапуск качал бы то же самое заново. Для обложки у generate так уже сделано (`cover_url`).
- **Расширить задание `video`** отвергнуто: у видео своя логика yt-dlp, высоты и `#VIDEOGAP`; общий обработчик стал бы набором веток.

## Последствия

- Проверки ссылки (формат, размер, адреса домашней сети) живут в web; воркер доверяет файлу в `in/`.
- Перезапуск использует уже скачанный `in/image.<ext>`; для обновлённой картинки нужно ставить новое задание.
- Имя нового файла может отличаться от старого только регистром расширения; удаление «старого» файла обязано сравнивать имена без учёта регистра, иначе удалится новый файл (найдено ревью, F1).
- Новый тип задания приходится вносить в `BUSY_TYPES`, `HANDLERS` и подписи очереди вручную.
