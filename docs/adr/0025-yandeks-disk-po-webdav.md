# 0025. Яндекс Диск подключается по WebDAV с паролем приложения

## Контекст

Нужно хранилище «Яндекс Диск» с прямым сетевым подключением из контейнера: пользователь отказался ограничиваться папкой клиента на ПК.

## Решение

Яндекс Диск — частный случай общего типа `webdav` (`preset: "yandex"`, url `https://webdav.yandex.ru`): логин, пароль приложения Яндекса, путь папки. `WebDavStorage` ходит PROPFIND/GET/PUT/MOVE/DELETE/MKCOL через общий `karaoke_core.http.Http`, пишет файл во временный файл тома и отправляет PUT целиком, замену делает MOVE с `Overwrite: T`. Тот же тип без пресета подключает любой WebDAV (Nextcloud, NAS).

## Почему

- **Папка клиента Яндекс Диска на ПК, примонтированная в контейнер**, отвергнута: пользователь потребовал сетевое подключение, а синхронизацию держит сторонняя программа, о состоянии которой сервис ничего не знает.
- **REST API Диска с OAuth** отвергнут: нужна регистрация своего приложения у Яндекса, а WebDAV — официальный доступ без неё.
- **rclone в образе** отвергнут: ещё один внешний бинарник со своей конфигурацией и секретами вне БД, тогда как весь исходящий HTTP проекта идёт через `Http` и подменяется `FakeHttp` в тестах.

## Последствия

- Пароль приложения хранится в БД в открытом виде, как пароль SMB; API его не возвращает (`has_password`).
- PUT целиком: большое видео сначала ложится во временный файл тома, обрыв посреди отправки начинает файл заново.
- Яндекс ограничивает скорость WebDAV — сканирование и копирование крупной библиотеки медленные; листинг кэшируется только на один проход.
- Расхождения других WebDAV-серверов в семантике MOVE/PROPFIND всплывут только в работе — тесты проверяют лишь маршруты `FakeHttp`.
